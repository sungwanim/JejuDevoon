# Spec: 한 번에 실행되는 단일 프로세스 앱 (빌드된 화면을 FastAPI가 서빙)

**Status:** ready-for-agent

## Problem Statement

센터 담당자(비개발자)가 앱을 써 보려면 지금은 터미널 두 개(FastAPI + Vite 개발 서버)와 Node 설치가 필요하다. 분석 엔진이 전부 Python이라 화면만 단독으로 돌릴 수는 없지만, 한 PC에서 쓰는 MVP에 앞·뒤 서버를 따로 띄우는 건 과하다.

## Solution

화면(React)을 미리 빌드한 정적 파일(`frontend/dist`, 약 0.4MB)을 저장소·제출 zip에 포함하고, FastAPI가 같은 포트에서 API와 화면을 함께 서빙한다. `실행.bat` 하나를 더블클릭하면 서버가 `127.0.0.1`에서 뜨고 브라우저가 자동으로 열린다. 사용자 PC에는 Python만 있으면 된다(Node 불필요, 개발자만 필요). API·분석 엔진·테스트는 그대로다.

## User Stories

1. 센터 담당자로서, `실행.bat`을 더블클릭하면 앱이 열리길 원한다. 터미널 명령을 몰라도 쓸 수 있도록.
2. 센터 담당자로서, Node를 설치하지 않아도 되길 원한다. 설치 허들을 줄이려고.
3. 심사위원으로서, README의 명령 한두 줄로 앱을 띄우길 원한다. 재현 가능성을 확인하려고.
4. 심사위원으로서, API 키 없이도 데모 모드로 화면을 확인하길 원한다. (`JEJU_LLM=fake`)
5. 개발자로서, 화면 코드를 고친 뒤 `npm run build` 한 번으로 서빙용 파일을 갱신하길 원한다.
6. 개발자로서, 개발 중에는 기존처럼 Vite 개발 서버(핫리로드)를 쓰길 원한다.
7. 센터 담당자로서, 서버가 내 PC 안에서만 접근되길 원한다(127.0.0.1 바인딩). 분석 결과·키가 외부에 노출되지 않도록.
8. 센터 담당자로서, `.env`가 없거나 키가 비었을 때 무엇을 해야 하는지 화면/콘솔 안내를 보길 원한다.
9. 센터 담당자로서, 포트가 이미 사용 중이면 알아듣기 쉬운 메시지를 보길 원한다.
10. 개발자로서, 빌드 결과가 없을 때(`dist` 없음) API는 정상 동작하고 화면 경로만 안내 메시지를 주길 원한다.
11. 제출 담당자로서, 제출 zip에 빌드된 화면이 들어 있고 비밀값 스캔은 여전히 통과하길 원한다.
12. 제출 담당자로서, zip에 `node_modules`·`.env`는 계속 빠지길 원한다.

## Implementation Decisions

- **구조 유지:** FastAPI 4개 엔드포인트(`/api/runs`, `/api/runs/{id}`, `/api/runs/{id}/result`, `/api/catalog`)와 프론트 `api.ts`(상대경로 `/api`)는 변경하지 않는다. 같은 출처에서 서빙하므로 CORS 설정은 필요 없다.
- **정적 서빙:** `frontend/dist`가 있으면 앱 생성 시 `/api` 이외의 경로를 정적 파일로 서빙(루트는 `index.html`). `/api/*`가 정적 마운트보다 우선해야 한다. `dist`가 없으면 `/`에서 "화면이 빌드되지 않았습니다. `npm run build`" 안내 JSON/텍스트만 반환하고 API는 정상.
- **진입점:** `python -m jejuagent` (backend 패키지에 `__main__`)가 `uvicorn`을 `127.0.0.1`, 기본 포트 8000으로 띄우고, 서버가 준비된 뒤 기본 브라우저로 URL을 연다. 포트 사용 중이면 한국어 안내 후 종료. `--port`, `--no-browser` 옵션만 제공.
- **런처:** 프로젝트 루트 `실행.bat`: 루트의 `.venv`가 있으면 그 Python으로 `-m jejuagent` 실행, 없으면 `python`(PATH)으로 시도하고 실패 시 설치 안내. 키 없는 데모용 `실행-데모.bat`(`JEJU_LLM=fake`)을 함께 둔다.
- **`dist` 커밋:** `.gitignore`에서 `frontend/dist/`를 제거해 저장소에 포함한다. 빌드 산출물은 약 0.4MB(JS 1개, CSS 1개)로 용량 부담이 없다. 빌드 파일 이름이 해시라 재빌드마다 변경되므로, 화면 코드를 바꾸면 반드시 재빌드 후 커밋한다는 규칙을 문서에 적는다.
- **제출 zip:** 제출 스크립트가 `frontend/dist`는 포함하고 `node_modules`는 계속 제외한다. 현재 `dist` 이름 전체 제외 규칙을 `frontend/dist`만 허용하도록 바꾸고, zip 재검사의 비밀값 스캔은 그대로 돌린다(JS 번들도 텍스트로 스캔).
- **보안 점검 결과(결정 근거):** 빌드 번들에는 키가 없다(프론트는 키를 쓰지 않고 키는 서버의 `.env`에서만 읽음). 다만 번들에 외부 URL이 들어가는지(OSM 타일 URL은 의도된 것)를 스캔 결과로 확인한다. 로컬 API에 인증은 없으므로 127.0.0.1 바인딩을 유지하고, 문서에 "공용 PC·원격 접속 금지"를 명시한다.
- **문서 갱신:** README, `docs/TESTING.md`, `docs/submission/user-manual.md`를 "더블클릭/명령 한 줄" 기준으로 고친다. 개발 모드(Node 2터미널)는 개발자 섹션으로 내린다.

## Testing Decisions

- 좋은 테스트는 HTTP 동작만 본다(내부 구현 아님). 가장 높은 기존 seam인 앱 팩토리의 HTTP 인터페이스(`TestClient`)를 사용한다. 새 seam은 만들지 않는다.
- 테스트 항목: ① `dist`가 있을 때 `/`가 `index.html`, `/assets/...`가 정적 파일을 반환 ② `/api/catalog` 등 API가 정적 서빙에 가려지지 않음 ③ `dist` 없을 때 `/`는 안내 응답, API는 정상 ④ 존재하지 않는 `/api/...`가 `index.html`이 아닌 404 ⑤ 제출 zip에 `frontend/dist`가 들어가고 `node_modules`·`.env`는 없음(기존 제출 스크립트 테스트/스캔 확장).
- 선행 사례: 기존 API 테스트(`backend/tests`의 앱 생성 후 `TestClient` 호출)와 제출 스크립트 스캔.
- `__main__` 런처의 브라우저 열기는 자동 테스트 대상 아님(수동 확인: `실행-데모.bat`).

## Out of Scope

- Electron/pywebview 등 네이티브 창 패키징, 실행 파일(.exe) 배포, Python 자동 설치.
- 인증·HTTPS·다중 사용자 지원.
- 프론트 단독(Pyodide/TypeScript 재작성) 전환.
- OSM 지도 타일의 오프라인화(인터넷 필요, 문서에 명시).
- 엔진·API 스키마·프론트 기능 변경.

## Further Notes

- 남는 허들은 Python 3.14 설치 하나다. 매뉴얼에 설치 안내와 `.venv` 만드는 한 줄을 넣는다.
- 확인하지 못한 것: 빌드된 화면을 FastAPI로 서빙했을 때 지도 타일·결과 iframe이 개발 서버와 동일하게 동작하는지(구현 후 수동 확인 필요). 커밋은 사용자가 직접 한다.
