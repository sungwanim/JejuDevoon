# 실행환경·매뉴얼

제주 공공데이터 분석 Agent의 설치·실행 절차, 의존성, 환경변수, 사용자 매뉴얼, 오류와 제약사항을 한 문서에 모았다. 루트 `README.md`는 같은 절차의 요약이다. 이 Agent의 특징은 농업·기상·환경 등 **도메인이 다른 데이터를 카탈로그로 받아, 데이터 구조에 맞는 분석 코드를 직접 작성·검증·저장·재사용**하는 데 있다.

> **먼저 읽어 주세요**
> - 앱에는 합성(가짜) 데이터가 없다. 가격·기온은 허브·농업기상 API로 받은 **실데이터 스냅샷**(`snapshots/live/`)을 쓴다. 스냅샷이 없으면 그 데이터셋은 목록에 나타나지 않는다.
> - 실제 GPT-4o로 질문 15개를 돌려 본 결과는 `3_결과_설명자료.md` 4절에 있다. **되는 질문과 안 되는 질문이 섞여 있다.** 성공률 수치는 없다.
> - 수익을 보장하지 않는다. 재배 적합도와 한계온도(동해 등)는 판정하지 않는다.

## 1. 실행 환경

센터 Agent 운영 PC 최소사양(Intel Core i7-8700 / GTX 1060 / RAM 32GB)을 기준으로 적었다. 이 앱은 GPU를 쓰지 않는다(LLM은 OpenAI 서버에서 실행). 이 사양의 PC에서 실행해 본 적은 없고(**미확인**), 개발 PC(Windows 11)에서만 확인했다.

| 항목 | 요구 |
|---|---|
| OS | Windows 10/11 (개발·확인은 Windows 11). 다른 OS는 확인하지 않았다 |
| Python | 3.14 (개발 환경 3.14.8) |
| Node.js | 화면 코드를 고칠 때만 필요(개발 환경 v24.21.0, npm 11.19.0). 실행만 한다면 불필요 |
| 네트워크 | OpenAI API 호출, 지도 타일과 결과 화면의 차트 라이브러리(CDN) 로딩에 인터넷이 필요하다 |
| 키 | `OPENAI_API_KEY` 필수. 나머지 키는 실데이터를 새로 수집할 때만 |

## 2. 설치 절차

저장소(또는 제출 zip을 푼 폴더) 루트에서 PowerShell로 실행한다.

```powershell
# 1) 파이썬 가상환경과 의존성
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

# 2) 프런트엔드 의존성: 화면 코드를 고칠 때만 필요(빌드된 화면 frontend/dist 가 포함되어 있다)
cd frontend
npm ci
cd ..

# 3) 환경변수 파일: 키는 직접 입력한다. 채팅·문서에 붙여넣지 않는다
copy .env.example .env
notepad .env
```

## 4. 환경변수 예시

`.env`는 프로젝트 루트에 둔다. git과 제출 zip에서 제외된다. 예시(`.env.example`, 값은 비어 있다):

```
OPENAI_API_KEY=
JEJU_HUB_PROJECT_KEY=
DATA_GO_KR_SERVICE_KEY=
JEJU_DATA_MODE=
```

| 변수 | 필수 | 용도 |
|---|---|---|
| `OPENAI_API_KEY` | **실제 분석에 필수** | OpenAI GPT-4o 호출. `sk-`로 시작하는 OpenAI 키여야 한다(다른 서비스 키를 넣으면 401) |
| `JEJU_HUB_PROJECT_KEY` | 가격 데이터를 새로 수집할 때 | 제주데이터허브의 **프로젝트 키**(마이페이지 > 프로젝트 관리). 거래 통계·이동평균 두 데이터를 그 프로젝트에 담아야 한다 |
| `DATA_GO_KR_SERVICE_KEY` | 기온 데이터를 새로 수집할 때 | 공공데이터포털 서비스 키. 농업기상 "관측지점 상세정보"와 "상세 관측데이터" 두 API를 각각 활용신청해야 한다 |
| `JEJU_DATA_MODE` | 선택 | `live`면 가격 데이터를 요청 때 API로 다시 받고 실패하면 마지막 스냅샷으로 동작. 비우면 스냅샷만 읽는다 |
| `JEJU_LLM` | 선택(`.env.example`에 없음) | `fake`면 키 없이 화면 흐름만 확인하는 데모. 실제 분석은 하지 않는다. `run-demo.bat`이 지정한다 |

키는 오류 메시지·로그·실행 기록에 남지 않게 처리했다(OpenAI 오류 문구에 비치는 마스킹된 키 조각도 가린다).

## 5. 실행 절차

### 5.1 가장 간단한 방법
1. 키가 든 `.env`를 만든다(4절).
2. 루트의 **`run.bat`을 더블클릭**한다. 검은 창은 닫지 않는다(닫으면 서버가 꺼진다). 서버가 `127.0.0.1:8000`에서 켜지고 브라우저가 자동으로 열린다.
3. 포트가 이미 쓰이면 안내 후 종료한다. 다른 포트는 `.\run.bat --port 8001`, 브라우저를 열지 않으려면 `--no-browser`.

같은 동작을 명령으로: `cd backend` 후 `..\.venv\Scripts\python.exe -m jejuagent`.

키 없이 화면 흐름만 보려면 `run-demo.bat`. 어떤 질문이든 "데모 모드라 분석하지 않는다"는 불가로 끝나고, 단계 진행과 생각 과정 표시만 확인된다.

### 5.2 데이터 준비
앱은 `snapshots/live/`의 실데이터 스냅샷 3개(`jeju_weather_daily`, `jdh_agri_daily_trade`, `jdh_agri_trade_moving_avg`)와 `data/`의 CSV 5종, DEM을 읽는다. 스냅샷이 제출물에 들어 있으면 따로 할 일이 없다. 새로 수집하려면 `backend/`에서:

```powershell
# 허브 거래 통계·이동평균 (JEJU_HUB_PROJECT_KEY)
..\.venv\Scripts\python.exe -m jejuagent.data.live.collect hub 20240101 20251231
# 농촌진흥청 농업기상 제주 지점 일자료 (DATA_GO_KR_SERVICE_KEY)
..\.venv\Scripts\python.exe -m jejuagent.data.live.collect agri-weather --days 20240101 20241231
```

수집이 한도·오류로 멈추면 같은 명령을 다시 실행하면 이어받는다. 허브와 농업기상 수집은 실제 키로 확인했다.

### 5.3 개발자용
화면 코드를 고친 뒤에는 `cd frontend; npm run build`로 `frontend/dist`를 다시 만들어 함께 커밋한다(빌드 결과를 저장소에 포함한다). 핫리로드는 백엔드를 `--no-browser`로 띄우고 `cd frontend; npm run dev` 후 `http://localhost:5173`.

### 5.4 자동 테스트
```powershell
.venv\Scripts\python.exe -m pytest backend/tests -q
```
키·네트워크가 필요 없다(LLM은 가짜, 외부 API는 가짜 서버). 마지막 전체 실행: **283개 통과**(약 3~4분). 테스트는 `backend/tests/synth_fixtures.py`의 테스트용 가짜 데이터를 쓰고 실데이터 스냅샷은 보지 않는다.

## 6. 사용자 매뉴얼

### 6.1 화면 구성
위에서 아래로:
1. **대화창:** 내가 보낸 질문과 Agent의 한 줄 응답.
2. **지도:** 제주 지도(CARTO 타일, OpenStreetMap 데이터). 클릭하면 분석할 위치가 정해지고 "선택 위치: 위도, 경도"가 표시된다.
3. **진행 표시:** ① 요청 규격화 → ② 데이터 선택 → ③ 로드·Profile → ④ 분석 → ⑤ 렌더. 진행 중인 단계가 강조되고 끝나면 결과 상태 배지가 붙는다.
4. **생각 과정:** 분석하는 동안 한 줄씩 쌓인다(6.4절).
5. **질문 입력창:** Enter로 보낸다(줄바꿈은 Shift+Enter). 분석 중에는 잠긴다.
6. **결과 영역:** 결과 HTML. [결과를 HTML 파일로 저장] 버튼으로 내려받을 수 있다.
7. **데이터 선택 패널:** 쓴 데이터, 뺀 데이터와 이유, 답할 수 없는 하위 질문.
8. **실행 기록:** 접혀 있는 개발자용 패널.

### 6.2 지도 클릭
- "여기", "이 땅", "내 밭"처럼 특정 장소를 가리키는 질문은 먼저 지도에서 클릭한다. 위치가 필요 없는 질문은 클릭하지 않아도 된다.
- 지명·주소를 글로 쓰는 방식은 좌표로 바꾸지 못한다.
- 바다나 제주 본섬 밖(추자도, 마라도 등)을 클릭하면 "범위 밖"으로 안내하고 분석하지 않는다.

### 6.3 질문하기
질문은 평소 말투로 쓴다. 아래 5개는 **2026-11-20에 실제 GPT-4o로 한 번씩 돌려, 기대한 상태로 끝나고 답의 숫자가 원자료와 맞는 것을 확인한 질문**이다(지도 클릭 불필요).

| # | 질문 | 기대 | 확인한 답 |
|---|---|---|---|
| 1 | 제주공항 소음측정소 중 소음도가 가장 높은 곳은? | 답변 완료 | 도평동. 원자료에 `도평동`(평균 80.2)과 `도평동591`(81.7)이 따로 있어 후자가 조금 더 높다 |
| 2 | 2024년 제주 관측소 중 연평균기온이 가장 높은 곳과 가장 낮은 곳은 어디야? | 답변 완료 | 높은 곳 서귀포 하례리 19.3℃, 낮은 곳 제주시 금악리 16.3℃ |
| 3 | 2024년 제주에서 비가 가장 많이 온 달은 언제야? | 답변 완료 | 6월 |
| 4 | 채소 가격 데이터는 어떤 기간까지 있어? | 답변 완료 | 2025년 12월 31일까지 |
| 5 | 주식 추천해줘 | **불가(걸러짐)** | 쓸 수 있는 데이터가 없다는 이유로 불가 |

- 질문 하나에 대략 20~60초, 호출 비용은 약 $0.02~0.09였다.
- 같은 질문이라도 응답 문장은 조금 달라질 수 있다(온도 0, 고정 시드를 쓰지만 완전한 재현은 보장되지 않는다).
- **되지 않은 질문도 있다.** "마늘이랑 양파 중 면적당 조수입이 나은 건?", "2020년 이후 서귀포시 감귤 생산 추세는?", "제주 도시숲 조성 사업량을 연도별로 보여줘"는 실패했고, "최근 3년간 시설채소 재배면적이 늘고 있는 작목은?"은 데이터가 있는데도 불가로 끝났다. 전체 기록은 `3_결과_설명자료.md` 4절.
- 지금 쓸 수 있는 데이터: 허브 가격·거래 통계(17개 품종, 2024-01-02~2025-12-31)와 이동평균, 서귀포시 감귤 생산(읍면동별 2012~2022), 제주 채소류 재배현황(연산 15-16~20-21), 제주 기상 관측소 기온·강수(16개 지점, 2024년), 제주공항 항공기 소음(2010~2023), 도시숲 조성사업(2007~2021), 환경소음(2024). 이 범위 밖 질문은 "기간 밖" 또는 데이터 없음으로 안내한다.
- 쉬운 설명을 원하면 질문에 "쉽게 설명해줘"를 쓴다. 앱이 요청 성격에 따라 보고서형, 그림형, 지도형 중 하나로 정한다. 형식을 고르는 버튼은 없다.

### 6.4 생각 과정
분석하는 동안 화면의 **"생각 과정"** 패널에 에이전트가 단계마다 내린 결정과 이유가 쉬운 말로 한 줄씩 쌓이고, 끝난 뒤에도 남는다. 예:
- 요청 이해: "요청을 이렇게 이해했어요: …", 필요한 분석, 결과 형식.
- 데이터 고르기: "사용할 데이터 N개를 골랐어요: 데이터 (이유)", 제외한 데이터와 이유, 서로 다른 데이터의 관계를 묻는 요청이면 연결 근거를 따진 결과.
- 데이터 불러오기: 행 수, 지점 고도.
- 분석: 작업을 몇 개로 나눴는지, 작업마다 검증된 모듈을 재사용하는지·고쳐 쓰는지·새 코드를 만드는지와 이유, 코드 검증 통과·실패와 재시도 여부.
- 결과 만들기: 결과 형식, 근거 없는 숫자 문장을 몇 개 걸렀는지.

이 문장들은 LLM의 숨은 추론이 아니라 각 단계가 실행 기록에 남기는 결정과 그 이유를 옮긴 것이다.

### 6.5 결과 읽는 법
위에서부터: 요약(문장 속 숫자는 계산 결과와 대조해 근거 없는 문장은 자동으로 지운다) → 분석 흐름도 → 표·차트·지도 → 답하지 못한 부분과 이유 → 사용한 데이터/제외한 데이터와 이유 → 근거와 한계 → 데이터 출처와 이용조건.

| 배지 | 뜻 |
|---|---|
| 답변 완료 | 질문에 모두 답함 |
| 일부 답변 | 일부는 데이터가 없거나 분석이 실패해 답하지 못함. "답하지 못한 부분" 확인 |
| 되묻기 | 정보가 모자라 Agent가 질문함 |
| 불가 | 다루는 범위가 아니거나 쓸 데이터가 없어 답하지 않음 |
| 실패 | 분석 중 오류. 질문을 단순하게 바꿔 다시 해 본다 |

### 6.6 되묻기와 불가
- 위치가 필요한 질문인데 지도를 클릭하지 않았다면 "어느 위치를 분석할까요?"라고 되묻는다. 지도를 클릭하고 "여기요"처럼 짧게 답하면 이전 질문과 이어서 분석한다. 서버를 재시작하면 이어쓰기 상태가 사라진다.
- 다음은 "불가"와 이유가 나온다: 가진 데이터에 없는 주제(주식, 코인, 맛집 등), 제주 본섬 밖이나 바다 위 클릭, 서로 연결할 근거가 없다고 판단한 두 데이터의 관계 질문(이 판단은 아직 믿기 어렵다, 한계 참고).

### 6.7 자주 묻는 질문
- **결과를 저장하고 싶어요.** [결과를 HTML 파일로 저장]. 차트·지도는 인터넷이 연결되어야 보인다.
- **차트나 지도가 비어 있어요.** 인터넷·방화벽(CDN 차단)을 확인한다. 안 되면 표·좌표 표로 대신 보인다. 소음측정소처럼 좌표가 없는 데이터는 지도 형식이어도 점이 찍히지 않을 수 있다(답과 표는 맞다).
- **개인정보를 입력해도 되나요?** 쓰지 않는다. 질문 문장은 그대로 OpenAI로 전송된다.

## 7. 오류와 제약사항

| 증상 | 원인·조치 |
|---|---|
| "OPENAI_API_KEY가 없습니다" 또는 `OpenAI 호출 실패: AuthenticationError` | `.env`의 키를 확인한다. OpenAI 키(`sk-`)여야 한다 |
| 가격·기온 데이터셋이 목록에 없다 | `snapshots/live/`가 없다. 5.2절로 수집한다 |
| 허브 수집이 403 `Forbidden` | 프로젝트 키가 아니거나 해당 API를 프로젝트에 담지 않았다. 실제 키와 가짜 키가 같은 응답이라 서버만으로는 구분되지 않는다 |
| 농업기상 수집이 키 오류 | 두 API를 각각 활용신청했는지 확인한다 |
| 포트 사용 중 | `--port`로 다른 번호 |
| 차트·흐름도·지도가 안 보임 | CDN(jsdelivr, unpkg)과 지도 타일(CARTO) 접속 확인. 대체 표시가 나온다 |

제약:
- **실행 상한:** 한 번에 LLM 호출 25회, 5분, 코드 실행 1회 60초, 작업당 코드 시도 2회(생성 + 수정 1회). 재계획은 없다.
- **관측소 범위:** 기온 관측소 16개의 고도는 18~208m(저지대 농경지 위주). 한라산 고지대 값은 실측이 아닌 외삽이다.
- **범위:** 제주 본섬. 추자도·마라도는 범위 밖. 지점은 지도 클릭으로만 지정한다.
- **DEM:** 90m 격자 고도 조회뿐. 경사·사면·일사는 반영하지 않는다. 바다 마스크는 추정이다.
- **판정하지 않는 것:** 한계온도(동해 등)로 재배 가능 여부, 재배 적합도, 수익.
- **데이터 한계:** 감귤은 서귀포시뿐. 채소 재배현황은 도 전체 단위·조수입 기준(2021년 자료). 항공기 소음은 제주공항만, 측정소 좌표 없음. 환경소음의 위경도는 TM 좌표를 변환한 추정(오차 약 1km).
- **서버 재시작:** 진행 중 실행과 되묻기 대화는 메모리에만 있다(`runs/`에는 실행 기록이 남는다).
- **보안:** 단일 사용자 로컬 사용을 가정한다. 서버는 `127.0.0.1`에만 열리고 인증이 없다. 생성 코드 실행기는 보안 샌드박스가 아니다. 공용 PC나 외부 노출 금지.
- **저작권·귀속:** 결과물은 제주빅데이터센터에 귀속된다(대회 규정).
