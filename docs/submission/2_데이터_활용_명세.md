# 데이터 활용 명세

작성 기준: 코드, 카탈로그(`catalog/`), 수집한 스냅샷(`snapshots/live/`), 실행 기록에서 확인한 사실만 적었다. 확인하지 못한 것은 "미확인"으로 적었다. 이 문서는 필수 데이터 사용 내역, 출처·이용조건, 전처리·분석 흐름, 외부 데이터·AI·API·오픈소스 목록을 담는다.

## 1. 데이터 원칙

- 이 Agent는 한 도메인에 묶이지 않는다. 농업(가격·감귤·재배현황), 기상(농업기상 관측소), 환경(소음), 도시(도시숲) 등 **도메인이 다른 데이터를 같은 카탈로그에 두고, 데이터마다 맞는 분석 코드를 작성한다.**
- 공공데이터포털 데이터셋과 제주데이터허브 데이터만 쓴다. 문헌·논문·보도에서 옮긴 수치는 코드와 결과에 쓰지 않는다. 그래서 문헌 기반 재배 기준표와 적합도 판정 기능은 코드에서 제거했다.
- **앱에는 합성(가짜) 데이터가 없다.** 테스트용 가짜 데이터는 `backend/tests/synth_fixtures.py`에만 있고 앱 동작·제출 데이터에 쓰이지 않는다.
- 수집한 스냅샷이 없는 데이터셋(`optional`)은 카탈로그에 나타나지 않는다. 로드에 실패할 데이터를 고르지 않게 하려는 것이다.

## 3. 필수 데이터(제주데이터허브) 사용 내역

대회의 필수 데이터(제주데이터허브) 1종 이상 사용 요건에 대응하는 데이터는 다음 4종이다.

| 데이터 | 방식 | 사용처 |
|---|---|---|
| 농산물 품종별 일일 거래 통계 | 허브 API(프로젝트 키)로 수집 | 가격 추세·변동성 분석(검증된 모듈 `market-price-trend-volatility`) |
| 농산물 품종별 거래 이동평균 | 허브 API로 수집 | 가격 이동평균 질문. 값 `0.00`은 결측으로 처리 |
| 서귀포시 감귤 생산 정보 | 허브에서 받은 CSV | 읍면동별 생산·면적 분석. **제주시 데이터는 없다** |
| 제주채소류재배현황 | 허브에서 받은 CSV | 작목별 면적당 조수입·재배면적 추세·순위(검증된 모듈 `market-crop-economics`). 비용이 없어 조수입 기준 |

허브 API 호출 규격은 `data/docs/schemas/`의 명세서 두 개에 있다. **명세서에 적힌 API ID와 실제로 동작한 API ID가 달랐다.** 허브 화면의 호출 주소에서 확인한 ID(거래 통계 `13t6aat1…`, 이동평균 `0106aa36…`)를 코드에 썼다(`data/live/hub.py`). 명세서의 ID로는 같은 프로젝트 키로 403이 났다. 허브 거래 데이터가 어느 시장의 것인지는 명세에 없어 **미확인**이다.

## 5. 전처리와 분석 흐름

1. **카탈로그:** 데이터셋마다 JSON(id, 제목, 출처, 이용조건, 공간·시간 단위, 기간, 컬럼의 이름·의미·단위·`role_hint`·`parse`)을 `catalog/`에 둔다.
2. **로더(`catalog/loader.py`):** CSV는 utf-8 시도 후 cp949로 읽고 날짜·숫자 컬럼을 `parse` 규칙으로 바꾼다. 공백을 정리하고, 허브 스냅샷의 문자열 숫자를 숫자로 바꾸며 이동평균 `0.00`은 결측으로 바꾼다. 항공기 소음은 제주공항 행만 읽고 소음도 0과 빈 값·`-`을 결측으로 본다(결측 275건, 약 32%). 환경소음은 TM 좌표(km)를 중부원점 TM(남북 가산 550,000m)으로 보고 위경도로 변환한다. 이 가산값은 알려진 위치와의 대조로 정한 **추정**이고 오차는 약 1km일 수 있다.
3. **Profile(`catalog/profile.py`):** 행 수, 컬럼별 dtype·결측률·범위·고유값 수·샘플, 내용 해시를 만든다. LLM은 이 요약만 보고(원본 전체가 아님) 코드를 짠다.
4. **데이터 선택(② 단계):** LLM이 카탈로그 요약에서 쓸 데이터와 제외 이유를 고르고, 규칙이 기간·지역·컬럼·공간 단위 불일치를 교정한다. 서로 다른 두 데이터의 관계를 묻는 요청이면 의미상 연결할 근거가 있는지도 LLM이 판단해 근거가 없으면 불가로 끝낸다.
5. **지점 분석:** 지도 클릭 좌표 → DEM에서 고도 조회(바다·범위 밖이면 중단) → 관측소 기온을 고도 보정(고정 감률 6.5℃/km) + 역거리가중(IDW, p=2)으로 보간해 지점 기온을 추정하고 지표를 낸다. 한계온도 판정은 하지 않는다. 관측소 16개의 고도가 18~208m라 한라산 고지대는 외삽이다.
6. **분석 실행:** 검증된 시드 모듈 또는 LLM이 만든 pandas 코드를 격리 프로세스에서 실행한다(정적 검사 → 모의 데이터 → 실데이터 → `check()`). 실패하면 원인별로 1회 수정한다.
7. **렌더:** 계산된 산출물만 근거로 보고서를 만들고, 문장의 숫자가 계산 결과에 없으면 문장을 지운다. 출처·이용조건·한계를 자동으로 넣는다.

상세 방법: `docs/dem.md`, `docs/climate.md`, `docs/agent-flow.md`.

## 6. 사용하지 않은 데이터와 이유

| 데이터 | 이유 |
|---|---|
| 문헌 기반 재배 기준표·적합도 | 데이터 원칙(공공데이터포털 + 허브만)에 맞지 않아 제거 |
| 한계온도(동해 등) 판정 | 같은 이유와 1차 출처 확인 불가. 극최저기온·저온 일수는 참고 지표로만 |
| 경사·사면·일사 | DEM 90m는 고도 조회용. 모델링 없음 |
| 공공데이터포털 도·소매 가격정보, 농축수산물 표준코드 | 허브 가격 데이터와 품종·단위 이름 대응을 문서로 확인하지 못해 명세와 문서를 모두 뺐다 |
| 농업기상 생장도일 | 작물 코드 미확인, 사용하지 않아 명세를 뺐다 |

## 7. 개인정보·민감정보

데이터셋은 읍면동·도·측정지점 단위 통계와 품종별 거래 통계이며 개인정보·금융정보는 없다. API 키는 `.env`에서만 읽고 제출물에 포함하지 않는다(`scripts/make_submission.py`가 제출 zip을 만들 때 비밀값 형태 문자열을 검사한다). 생성 코드 실행 프로세스는 허용 목록 방식으로 환경변수를 제거해 키를 넘기지 않는다. 저장되는 분석 모듈에서는 개인정보를 제거한다(`modules_lib/privacy.py`, 호칭 기반 휴리스틱). 사용자 질문 문장은 그대로 OpenAI로 전송되므로 개인정보를 쓰지 않는다.

## 8. 외부 데이터·API·AI·오픈소스 선언

### 8.1 사용한 AI 모델

| 구분 | 모델 | 근거 |
|---|---|---|
| 런타임 LLM | OpenAI **GPT-4o**(`gpt-4o`, `backend/jejuagent/llm/openai_client.py`) | 단일 모델. 다른 LLM은 쓰지 않는다 |
| 호출 설정 | `temperature=0`, 고정 seed, Structured Outputs(`json_schema`, `strict: true`) | `OpenAILLM.build_kwargs` |
| 개발용 AI 모델 | **Claude Opus 5.5**, **Claude Sonnet 5.5**(Anthropic) | 설계 문서, 코드, 테스트, 제출 문서 작성에 사용. 앱이 실행 중에 호출하는 모델은 아니다. 요구사항·데이터 원칙·범위는 사람이 정하고 결과를 검토·실행했다 |
| 개발 도구 | **Claude Code**(Anthropic) | 위 두 모델을 쓰는 코딩 도구(CLI). 파일 수정, 명령 실행, 테스트 실행에 사용 |
| 테스트용 | `FakeLLM`(미리 정한 응답을 돌려주는 가짜) | 모든 자동 테스트가 이것으로 동작 |

런타임에서 LLM이 하는 일은 요청 규격화(1회), 데이터 선택과 관계 판단(1회), 분석 작업 계획과 코드 생성·수정·모듈 재사용 결정(작업별), 보고서 구성(1회)이다. 계산, 데이터 로드, 상태 전이, 상한 관리는 일반 Python 코드가 한다. 상한은 한 실행에 호출 25회·5분이다. LLM에 보내는 것은 질문 문장, 카탈로그·Profile 요약(원본 전체 아님), 계산 결과 요약이며 키는 보내지 않는다. 프롬프트 위치:

| 파일 | 내용 |
|---|---|
| `runner/stages/s1_parse.py`, `runner/request_plan.py` | ① 요청 규격화 프롬프트·스키마·규칙 |
| `runner/stages/s2_select.py`, `runner/selection.py` | ② 데이터 선택·관계 판단 프롬프트·스키마·규칙 |
| `analysis/prompts.py` | ④ 작업 계획, 코드 생성(코드 계약), 수정, 역할 매핑, 모듈 재사용 결정 |
| `render/spec.py` | ⑤ 보고서 구성 |

### 8.2 외부 API·서비스

| 서비스 | 용도 | 언제 호출 | 키 |
