# 데이터 활용 명세

작성 기준: 코드, 카탈로그(`catalog/`), 티켓 결과, `docs/HANDOFF.md`에서 확인한 사실만 적었다. 확인하지 못한 것은 "미확인"으로 적었다.

## 1. 데이터 원칙

공공데이터포털 데이터셋과 제주데이터허브 데이터만 쓴다. 문헌·논문·보도에서 옮긴 수치는 런타임 결과에 쓰지 않는다. 그 결과 문헌 기반 재배 기준표(`backend/jejuagent/criteria/criteria.json`)와 적합도 규칙은 코드로는 남아 있지만 **기본 꺼짐**(`JEJU_SUITABILITY=1`일 때만 켜짐)이며 제출 구성에서는 켜지 않는다.

## 2. 현재 상태 요약 (중요)

| 데이터 | 현재 앱이 쓰는 값 | 실데이터 여부 |
|---|---|---|
| 허브 품종별 일일 거래 통계 / 거래 이동평균 | `snapshots/` 합성 샘플 (6품종, 2024-01~03 영업일) | **합성.** 실데이터 수집 코드는 완성, 허브 프로젝트 키가 없어 실호출은 확인하지 못함 |
| 서귀포시 감귤 생산 정보 | `data/` CSV 원본 (읍면동 15 x 2012~2022) | 실데이터 |
| 국토지리정보원 DEM 90m | `data/` 6개 도엽 | 실데이터 (고도 조회 용도뿐) |

## 3. 필수 데이터(제주데이터허브) 사용 내역

대회의 필수 데이터 1종 이상 사용 요건에 대응하는 허브 데이터 **4종**(거래 통계, 거래 이동평균, 서귀포시 감귤 CSV, 제주채소류재배현황 CSV)이다. 이 중 거래 통계·이동평균은 현재 합성 샘플이므로, 실데이터로 쓰는 필수 데이터는 감귤 CSV와 채소재배현황 CSV 2종이다. 카탈로그 항목(`catalog/*.json`)과 로더로 사용 내역을 적는다.

이용조건:
- 허브 API: 카탈로그의 `license`는 "제주데이터허브 이용약관(확인 필요)". 약관의 구체적 조건(상업 이용, 재배포 등)은 **미확인**이다.
- 감귤 CSV: 카탈로그에 "공공누리/공공데이터 이용조건(확인 필요)". 공공누리 유형은 **미확인**이다.
- 채소재배현황 CSV: 카탈로그에 "제주데이터허브 이용약관(확인 필요)". **미확인**.
- 원본 명세서(`data/docs/schemas/`)에 허브 API 두 종(거래 이동평균, 일일 거래 통계)의 호출 규격이 있다(`농산물품종별거래이동평균API.hwpx`, `농산물품종별일일거래통계API.hwpx`).

허브 거래 데이터가 어느 시장의 거래인지는 명세에 없어 **미확인**이다. 카탈로그 지역은 "제주(시장 미기재)"로 적었다.

## 5. 전처리와 분석 흐름

1. **카탈로그:** 데이터셋마다 JSON(id, 제목, 출처, 이용조건, 공간·시간 단위, 범위, 컬럼의 이름·의미·단위·`role_hint`·`parse`)을 `catalog/`에 둔다.
2. **로더 (`catalog/loader.py`):** CSV는 utf-8 시도 후 cp949 폴백으로 읽고(`df.attrs["encoding"]`), 날짜·숫자 컬럼을 `parse` 규칙으로 변환한다. 허브 API 스냅샷은 숫자가 문자열로 오므로 숫자로 바꾸고, 이동평균 `0.00`은 결측(NaN)으로 바꾼다. 감귤 CSV의 읍면동 이름 뒤 공백을 제거한다.
3. **Profile (`catalog/profile.py`):** 행 수, 컬럼별 dtype·결측률·범위·고유값 수·샘플, 내용 해시(`version_hash`)를 만든다. LLM은 이 요약만 보고(원본 전체가 아님) 코드를 짠다.
4. **데이터 선택 (② 단계):** LLM이 카탈로그 요약에서 고르고, 규칙이 기간 불일치·지역 불일치·없는 컬럼·공간 단위 불일치를 걸러 제외 이유 코드를 남긴다.
5. **지점 분석:** 지도 클릭 좌표 → DEM에서 고도 조회(바다·범위 밖이면 중단) → 관측소 기온을 고도 보정(고정 감률 6.5℃/km) + 역거리가중(IDW, p=2)으로 보간해 지점 기온을 추정, 지표 산출. 한계온도 판정은 하지 않는다. 교차검증은 합성 데이터에서 일 MAE 0.50 대 최근접 1.35이나, **진값이 6.5℃/km로 만든 합성이라 실제 성능이 아니다.**
6. **분석 실행:** 검토된(verified) 시드 모듈 또는 LLM이 생성한 pandas 코드를 격리 프로세스에서 실행한다(mock 데이터 검증 후 실데이터). 실패 시 원인별로 1회 수정한다.
7. **렌더:** 계산된 산출물만 근거로 보고서를 만들고, 문장의 숫자가 계산 결과에 근거가 없으면 문장을 지운다. 데이터 출처·이용조건·한계를 자동 삽입한다.

상세 방법: `docs/dem.md`, `docs/climate.md`, `docs/agent-flow.md`.

## 6. 채소재배현황 분석 (티켓 17, `catalog/`와 티켓 결과 확인 기준)

`catalog/jeju_vegetable_cultivation.json`이 등록되어 있고(카탈로그 5개 항목), 검토된 모듈 `market-crop-economics`가 연산·작목별 면적당 조수입(백만원/ha), 수량(톤/ha), 단가(원/kg = 조수입 x 1,000,000 / (생산량 x 1,000)), 재배면적 증감, 노지/시설별 순위를 계산한다(예: 20-21 월동무 면적 5,056ha, 조수입 106,434백만원 -> 21.05백만원/ha). 소분류 '기타(…)' 2종은 합계 성격이라 순위·추세에서 제외한다. 한계: 도 전체 단위(지점 차이 설명 불가), 조수입 기준(순이익 아님), 최신 연산 20-21·기준일 2021-08-09(오래됨). 허브 가격 품종과의 이름 매핑은 같은 이름인 `월동무` 하나만 연결했다(`backend/jejuagent/catalog/crop_name_map.json`). 지점 분석에서는 보조(auxiliary) 데이터로만 쓰인다. 검증은 가짜 LLM으로만 했고 실제 GPT-4o 동작은 미확인이다.

## 7. 사용하지 않은 데이터와 이유

| 데이터 | 이유 |

| 농업기상 관측데이터(농진청) | 공공누리 제4유형(변경금지)이라 분석 결과 사용 가능 여부를 문의한 뒤 결정. 코드 미연결, 키 필요, 제주 관측지점 목록 미확인 |

| 기상청 AWS 일자료 | API 미확인 (지점정보만 확인) |
| KAMIS 가격·표준코드 | 코드 체계 대응 미확인 |
| 문헌 기반 재배 기준표·적합도 | 데이터 원칙(공공데이터포털 + 허브만)에 맞지 않아 기본 꺼짐 |

| 경사·사면·일사 | DEM 90m는 고도 조회용. 모델링 없음 |

## 8. 개인정보·민감정보

데이터셋은 읍면동·도 단위 통계와 품종별 거래 통계이며 개인정보·금융정보는 없다. API 키는 `.env`에서만 읽고 제출물에 포함하지 않는다. 생성 코드 실행 프로세스는 허용 목록 방식으로 환경변수를 제거해 키를 넘기지 않는다. 저장되는 모듈에서는 개인정보를 제거한다(`modules_lib/privacy.py`, 호칭 기반 휴리스틱).
